# 跨国临床试验随机分组和揭盲控制台

源提示词摘要：研究中心按分层因素生成随机分组；药品管理员只见发药信息，研究角色正常情况下不可见治疗组；重复受试者和编号冲突被阻止；紧急揭盲需填写原因并形成不可删除审计记录，断网提交进入待处理队列。

## 技术栈

Nuxt 3、TypeScript、Element Plus、Pinia、Nuxt 路由、Axios、VueUse、VeeValidate、Zod、Vue I18n。

## 本地运行

```bash
npm install
npm run dev
```

开发端口：`62028`

## 可用流程

- 入组：机构、分层因素和受试者编号校验后生成分层区组随机号与治疗组。
- 防重复：相同身份标识或研究中心编号会拒绝再次入组。
- 角色隔离：研究者、药品管理员和监察员看到不同的分组隐藏规则。
- 安全审计：紧急揭盲要求原因，添加后只能追加，不能删除或改写。
- 离线队列：模拟离线提交进入待提交队列，联网后由授权人员确认入库。
- 药房发药：药品管理员凭随机号发药（发药编号与药盒批号由其负责），系统按批号与有效期近效期先出（FEFO）自动挑药盒；库存不足时退回并说明，不生成发药单。
- 台账对账：随机号、发药单、药盒批号合并为一份台账；同一随机号只留一份有效发药单，重复发药旧单自动作废。
- 批号召回：输入批号一次查出所有已发药受试者并一键换药；库存不足的退回并说明，分组与揭盲记录不动。
- 断网补录：断网时发药申请先留本中心，恢复后按次序（FIFO）补录，仅队列最靠前的申请可确认入库。
- 角色边界：药品管理员的药房视图与台账不含治疗组，审计时间线中揭盲原因与治疗组对其脱敏。
